# Agent Desk 独立项目架构

状态：设计基线，2026-10-22。替代[旧 HAPI 底座方案](archive/hapi-prototype-architecture.md)。

## 1. 产品归属与当前事实

Agent Desk 是独立的单人多 Agent 工作流产品。工作流模型、调度、界面、数据与接口由本项目定义；HAPI 等开源项目只提供经过选择的模块或参考实现。替换 HAPI 标题、Logo 和菜单不能作为独立项目交付。

2026-10-23 已建立自有 console、locald、contracts、工作流核心/服务、Runtime、OpenCode 适配、SQLite 存储与回环连接保护，完成一个简短真实 OpenCode + DeepSeek 工作流验证。具体实现与限制见 [独立版说明](independent-demo.md)。`hapi/` 保留旧原型，不参与独立版运行。**原生手机 App、真实手机跨网、中转和其他 CLI 执行仍未完成。** 本文的后续目标不能作为这些能力的完成证据。

配套文档：[产品交互](design/product.md)、[模块与复用](design/modules.md)、[接口约定](design/interfaces.md)、[迁移与验收](design/migration.md)。这些文档共同构成当前设计。

## 2. 目标目录

| 路径 | 职责 |
|---|---|
| `apps/console/` | 自有 React Web/PWA，电脑与手机界面；只有工作流和必要设置 |
| `apps/locald/` | 自有本机后台入口，组装 HTTP、事件、工作流服务、配置与执行器 |
| `apps/mobile/` | 后续 React Native/Expo App，共享协议，单独实现手机交互、配对与后台通知 |
| `apps/relay/` | 可选跨网中转；转发配对设备之间的加密帧，不运行 Agent |
| `packages/contracts/` | 自有请求、响应、事件、能力类型与运行时校验 |
| `packages/workflow-core/` | 定义、角色、状态机与调度决策，不导入网络或 CLI |
| `packages/workflow-service/` | 发布、派发、取消、审批、恢复与结果确认，只依赖领域和端口 |
| `packages/agent-runtime/` | CLI 探测、进程树、输入输出、退出与恢复生命周期 |
| `packages/agent-adapters/` | 各 CLI 的协议与能力映射，屏蔽厂商细节 |
| `packages/provider-config/` | 供应商设置、协议校验、秘密引用与进程环境注入 |
| `packages/storage/` | SQLite、迁移、事务、快照、事件和命令幂等记录 |
| `packages/transport/` | 本地、私网和中转连接，不决定任务如何执行 |
| `packages/ui/` | 品牌、排版与通用控件，不执行命令或读取数据库 |
| `scripts/` | E 盘优先的一键检查、启动、构建与诊断 |
| `third_party/` | 实际复用模块的来源、版本、许可证与改动记录 |
| `hapi/` | 现有原型与上游参考；不是新业务代码的归属目录 |

上述是目标目录，不表示各应用已经可启动。按实现阶段建立包，避免生成大量空工程。

这些是代码职责，不是十二个常驻服务。首版只需要一个本机后台进程：发布版由 locald 同时提供已构建的 console 静态文件和 API；开发时才额外启动 Vite。被选中的 CLI 是它管理的子进程。

## 3. 依赖和组合

界面仅依赖 API 客户端与 contracts；HTTP 路由校验后调用 workflow-service；服务通过端口访问运行器、存储和事件。核心端口为 `AgentCatalog`、`AgentRuntime`、`RunRepository`、`EventLog`、`SecretStore`、`DeviceTransport`，由 locald 组合入口注入实现。

workflow-core 不导入 Web、Bun、Socket.IO 或模型 SDK。CLI SDK、ACP、命令参数和 HAPI 数据结构止于适配器边界，不向产品协议扩散。注释重点解释权限、副作用、协议映射、事件顺序与恢复条件。

## 4. 工作流是唯一工作单元

层级为：工作流定义 → 一次运行 → 成员会话 → 消息、工具事件和审批。没有用户独立新建会话的入口。每个成员会话必须有 runId 与 memberId；历史运行不能与当前运行混排。

协调器可以同时工作。一种 CLI 可创建一个或多个成员，不强制用户安装多种软件；相同 CLI 不等于共用一个进程或上下文。首版采用协调器分派、成员汇报的模式；任意 DAG 编辑器属于后续能力。

模型只能提出派发和工具操作请求，由本机服务校验成员、目录、权限、并发与预算后执行。任务结果确认、进程停止、待审批分别表达，不把在线、空闲或退出当作任务完成。

## 5. CLI 和 API 设置

| CLI | 适配边界 | 配置约束 |
|---|---|---|
| OpenCode | 按实际版本支持的结构化事件/会话接口适配 | 项目或进程范围配置，不改全局 |
| Claude Code | 独立适配流事件、工具审批与恢复 | Anthropic 协议，不能直接注入 OpenAI 格式接口 |
| DeepSeek Harness | 按实际版本探测 ACP/JSON-RPC 能力 | 只注入其已支持的协议与模型配置 |
| Codex | 复用用户现有 CLI、登录和执行环境 | 不设置、写入、迁移或测试 API Key、Base URL、供应商及全局配置 |

当前真实联调仅使用用户指定的 DeepSeek 官方 `deepseek-flash`，以简短测试为主；禁止 GPT/Codex 联调。密钥不进入源码、公共协议、模型上下文或日志。配置只引用本机秘密，不回传原值；模型从配置读取，不硬编码当前测试模型为产品默认。

扫描分别呈现：已安装、版本、配置是否就绪、支持哪些动作。未真实执行时不能标为成功。协议转换必须作为显式适配器，不能宣称不同 CLI 天然兼容。

## 6. 电脑、手机与中转

locald 固定监听 `127.0.0.1`，数据库、目录和 CLI 留在电脑。不提供开放主机监听或公网端口映射开关。手机使用用户配置的私网 HTTPS 入口；后续可选已有服务器的出站中转，连接实现可替换，不改变工作流协议，也不要求购买服务器。

启动模式明确区分：电脑独用仅启动 locald；手机私网访问复用同一 locald，加用户配置的 HTTPS 隧道；中转模式额外启动服务器 relay，PC 建立出站连接，仍由本机执行任务。根脚本负责检测依赖、构建和启动，用户不必手动逐个启动内部包。

中转模式下 PC 与手机主动建立出站连接，不要求电脑开放公网端口。relay 只负责路由、限速、帧限制和连接状态；业务内容由配对设备加密。服务器不保存模型 Key，不执行电脑命令，但仍能看到连接时间、流量大小等元数据。

单人无账号体系，仍需设备配对、短期配对码、设备凭据及撤销手机能力。如果 Web 脚本也经服务器分发，服务器被篡改仍可能攻击客户端，不能只凭端到端加密宣称所有服务器风险已消除。

PWA 是首个手机入口，原生 App 单列里程碑。前台实时事件、后台通知和蜂窝网络连通性分别验证。[通信方案](connectivity.md)中的上游命令仅属于原型，不是新产品的启动命令。

## 7. 数据与恢复

SQLite 保存定义、运行、成员、审批、命令去重和事件日志。状态迁移与对应事件在同一事务提交，事件按运行递增 sequence。重连按 lastSequence 补发；重复事件不重复执行动作。

有副作用的命令先持久化再执行。相同 commandId 与相同请求返回原结果，不同请求体复用同一 ID 返回冲突。启动结果未知时标为待核对，禁止因超时或重连再次启动。重试明确创建新 attempt，保留旧输出。

原型日志与 HAPI sessionId 通过显式迁移映射进入新结构；不直接把旧数据库当作新协议。迁移保留源文件，只导入选定工作流和关联记录，不删除旧独立会话数据。

## 8. 独立版的完成标准

根目录脚本启动自有 locald 并提供 console，开发业务不再进入 `hapi/web` 或 `hapi/hub`。发布工作流、查看输出、审批、取消、补发和手机提交均使用自有接口。第三方复用模块保留来源与许可证。

验收分别记录单元测试、模拟 CLI、真实 CLI、浏览器手机视口和真实手机跨网结果。只有满足这些条件才称为独立项目版本，当前原型仅作为行为参考与迁移来源。
