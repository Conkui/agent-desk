# 产品与交互

状态：独立项目设计基线，2026-10-22。名称沿用 README 的 Agent Desk；品牌集中管理，与第三方署名和协议名解耦。

## 用户目标

单人在电脑选择已安装 CLI，指定协调器与可选工作 Agent；在电脑或手机发布任务、查看输出、补充要求、处理审批、确认结果。没有账号注册、组织管理或独立对话入口。

## 页面结构

| 页面 | 内容与操作 |
|---|---|
| `/workflows` | 名称、最近运行状态、成员数、待处理；新建、搜索、状态筛选 |
| `/workflows/new` | 任务、电脑、目录、协调器、是否兼任工作、成员职责；保存或发布 |
| `/workflows/:id` | 定义、最近运行、历史运行；新一轮与继续原运行明确区分 |
| `/workflows/:id/runs/:runId` | 本轮目标、状态、协调器与工作 Agent 安排；打开成员、处理审批、停止、确认 |
| `/workflows/:id/runs/:runId/members/:memberId` | 所属工作流、职责、消息与工具输出；补充消息、批准/拒绝、文件、终端 |
| `/settings/devices` | 电脑、扫描结果、配对手机、撤销设备 |
| `/settings/providers` | CLI、协议、服务地址、模型、密钥已保存状态及显式连接测试 |
| `/settings/appearance` | 语言、主题、字体及必要阅读偏好 |
| `/settings/about` | 自有名称、版本、复用模块、许可证与诊断 |

首个独立 Demo 可让工作流详情直接展示最近运行；内部仍区分 definitionId 与 runId。

## 会话安排

详情先展示目标和成员安排，再进入对话。协调器位于首位，注明是否工作；其他成员显示职责、CLI、状态和待处理请求。相同 CLI 多实例用成员名称区分，不能只重复显示 OpenCode。

手机每屏一个主要内容区，从成员返回原工作流；电脑可用窄成员栏切换。保留筛选、滚动及未发送草稿，按服务地址和工作流隔离。上一轮成员不能混入本轮。

## 状态与交互规则

- 工具未安装、未登录、电脑离线、尚无工作流、筛选无结果分别给出下一步。
- 区分派发中、工作中、等待输入、等待审批、断线、失败、结果待确认、确认完成、已停止。
- 离线展示最后同步时间；发布动作只保存草稿，不能显示为已执行。
- 审批展示命令/文件、工作目录、来源、有效范围，只针对仍有效的 requestId。
- 停止先显示停止中，收到退出确认后结束；部分成员停止失败仍可见。

## 界面约束

只有工作流与设置两个顶层目的地。待处理是工作流筛选与运行内入口，不堆叠欢迎卡、装饰性数字和重复列表。触控区至少 44 CSS px，长目录、职责、错误可以换行，状态不能被挤出屏幕。

“设备连接密码”“API Key”“上下文 Token”分别表达连接、供应商认证和文本计量，不共用“令牌”标签。不支持的能力说明原因，不放无效果按钮。
