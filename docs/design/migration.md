# 迁移计划与验收

状态：2026-10-23 开始实施。自有入口、协议、存储、工作流与 OpenCode 最小真实链路已建立；后续能力按下表区分，独立版说明见 [使用说明](../independent-demo.md)。

## 阶段 0：冻结产品边界

以 architecture、product、modules、interfaces 为基线。停止把新增产品功能写入 HAPI 的 App、Hub 或 shared。保留现有原型作行为与证据参考。本轮尚未完成的 HAPI 裁剪改动只属于草稿，不作为独立版交付，也不发布。

## 阶段 1：自有入口与协议

建立根 workspace、console、locald、contracts、workflow-core、storage。发布版由 locald 提供 console 静态文件与 API，开发时才额外启动 Vite；先用模拟 Runtime 验证工作流定义、运行、成员归属、命令去重和事件补发。删除独立会话作为产品能力，避免先复制上游页面再隐藏菜单。

验收：不进入 hapi 目录即可启动；Web 不导入 HAPI AppContext；数据有独立 schema/version；状态迁移和事件提交一致。模拟运行明确标注模拟，不能显示为真实 CLI 成功。

## 阶段 2：首个真实适配器

优先迁移已验证的 OpenCode 最小链路及项目范围 API 配置。把所需进程监督、输出解析、审批和恢复模块逐项抽取并记录来源。只做一次简短单成员和双成员验证，继续遵守 DeepSeek 与费用约束。

验收：自有界面发布 → 自有 API → Runtime → 真实 CLI → 结构化输出 → 自有事件；停止后确认退出。重复发布请求不能多开进程；工具失败、余额不足、断线有明确状态。禁止用 GPT/Codex 做联调。

## 阶段 3：自有交互和品牌

实现工作流列表、运行详情、成员输出与必要设置；提取而非整体复制对话组件。完成产品名称、Logo、favicon、PWA 名称、安装提示、文档与关于页归属。旧功能不迁入，历史数据不删除。

验收：一个工作流中的成员只显示在其运行内；单 CLI、同 CLI 多成员、协调器兼任、长输出、审批、失败、手机返回均可操作；不出现 HAPI 独立会话入口或未接线按钮。

## 阶段 4：手机连接

先验证 PWA 与本机私网连接，再实现可选 relay，最后做原生手机入口和后台通知。复用已有服务器仅是备选，不把新购 VPS 作为运行条件。

验收：真实手机 Wi-Fi/蜂窝网络发布、输出、审批、断线补发、设备撤销；服务端无明文 API Key；电脑休眠和网络不可达有明确反馈。中转与原生 App 未完成时准确标注，不以截图代替。

## 阶段 5：减少对原型的依赖

独立能力通过后，逐项移除旧产品实现，保留实际复用模块的来源、许可证和必要测试。迁移前后核对运行、成员、审批和历史数量；保留可恢复副本。是否归档整个 hapi 参考目录在迁移完成后决定，当前不批量删除它。

## 每阶段交付物

可执行入口、拥有清晰依赖的代码包、接口 schema、针对关键失败的测试、真实/模拟验证区分、未完成清单。未经用户要求，不提交、推送或发布。
